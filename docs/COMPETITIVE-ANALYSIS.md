# Competitive analysis / Análisis competitivo

Research date / Fecha: 2026-10-26. Nine relevant alternatives (free and commercial). Desk research from primary sources, not hands-on benchmarks or a definitive ranking. Features may depend on editions. Unpublished architecture, security controls and performance are **unknown**, not absent. Vendor accuracy/AI claims are not independently verified. No proprietary code copied.

## What to match, exceed and innovate / Estrategia

**Match (P1):** validated project config, bounded batches/crawling, state checkpoints, severity/WCAG filters, full review evidence, HTML/JSON/CSV, CI gates and histories. **Match (P2):** accessible dashboard, guided manual checks, baselines, scheduling, public API and integrations.

**Target improvements (unproven until accepted):** simple local setup without a database service; private data by default; ES/EN remediation and review workflows; run comparisons that flag engine/scope changes instead of marking unscanned pages resolved. These individual features exist elsewhere: the intended differential is their free, local and reproducible combination, not an invented unique capability.

**Innovation candidate:** a coverage ledger tying every conclusion to page, state, viewport, engine, scope and manual evidence; uncertain and untested results remain visible through comparisons. Demonstrate with deliberately changed scopes and engine versions. Do not use LLM output as proof or require paid inference. Curated offline guidance first, optional local inference later.

**Current competitive verdict:** AccessPilot is substantially behind the monitoring suites and assisted-testing tools. Phase 1 improved reliability, not competitive parity. No final comparative benchmark or release readiness claimed.

## Benchmark protocol / Protocolo

Maintain public deterministic fixtures: static, dynamic dialog, SPA navigation, nested frames, keyboard trap, contrast, authentication, failed resources and timeouts. Run identical URL/state/viewport/engine versions and hardware; record precision on labelled findings, missed known defects, wall time, peak whole-process-tree RSS/CPU, browser launches and failures. Compare Pa11y/Lighthouse locally with licence review; commercial trials need access and explicit account/data arrangements. No speed/accuracy superiority until comparable runs exist. Node process RSS alone excludes Chromium and is not a browser-memory benchmark.

English summary: close functional gaps with bounded, testable local workflows. Establish traceable bilingual evidence as the product goal; measure rather than advertise superiority. Commercial and manual trials remain pending.
